# UI/UX Design Brief --- Documentation Portal

## Design benchmark

Use this documentation page as the primary reference:

https://docs.paloaltonetworks.com/strata-cloud-manager/aiops/about

The goal is to reproduce the quality, structure and documentation
experience very closely while using original branding, original content
and neutral visual assets.

## 1. Overall visual direction

-   Enterprise documentation
-   Clean
-   Technical
-   Dense but not cramped
-   Trustworthy
-   Minimal
-   Content-first
-   Low visual noise

Do NOT make this look like a SaaS landing page.

## 2. Page composition

### Header

Create a compact documentation header with: - brand/product identity -
documentation context - utility links/actions where appropriate -
search/filter affordance

### Secondary/context navigation

Provide a clear documentation/product context area that establishes
where the user is in the documentation ecosystem.

### Left navigation

This is a primary visual element.

Top-level labels must be: - Folder 1 - Folder 2 - Folder 3 - Folder 4 -
Folder 5 - Folder 6 - Folder 7 - Folder 8 - Folder 9 - Folder 10 -
Release Notes

Requirements: - expandable/collapsible - compact typography - clear
indentation - active page treatment - active parent treatment - hover
state - keyboard focus - filter/search - scroll independently when long

### Main content

The article column should prioritize reading comfort.

Include: - breadcrumb - H1 - introductory paragraph - content sections -
links - lists - code examples - callouts - tables - images when needed -
previous/next controls

### Right rail

Use an "On This Page" style navigation for articles with multiple
headings.

It should: - remain visually secondary - identify the current section -
scroll to headings - work responsively

## 3. Typography

Prioritize: - highly legible sans-serif - strong H1 - clear H2/H3
hierarchy - restrained body size - compact navigation text - high
line-height for article paragraphs - distinct code typography

Avoid oversized marketing typography.

## 4. Color system

Start from a neutral documentation palette: - white/near-white
surfaces - dark charcoal text - muted gray secondary text - subtle gray
borders - restrained blue or project accent for links/active states

Do not copy Palo Alto Networks brand colors or logo treatment.

## 5. Spacing

Use a consistent spacing scale.

Important relationships: - compact header - narrow navigation spacing -
comfortable article line length - clear separation between article
sections - small gaps between breadcrumb items - predictable
card/callout padding

## 6. Components

Required reusable components: - Header - Documentation context bar -
Sidebar - Sidebar folder - Sidebar page item - Search - Breadcrumbs -
Article - Heading anchor - Code block - Callout - Table - On This Page -
Previous/Next - Footer

## 7. Interaction

Interactions should be subtle: - sidebar expand/collapse - active
navigation transition - hover/focus - search filtering - mobile drawer -
heading navigation

Avoid: - excessive parallax - 3D scenes - flashy scroll effects -
gradient-heavy backgrounds - decorative animation that competes with
documentation

## 8. Responsive behavior

Mobile: - hamburger/menu trigger - slide/drawer navigation - full-width
content - collapsible On This Page - sticky compact header

Desktop: - full documentation navigation - stable reading column - right
TOC when appropriate

## 9. Visual QA checklist

Compare implementation to the reference for: - header height - sidebar
width - content max-width - typography hierarchy - navigation density -
breadcrumb placement - article spacing - right rail alignment - border
treatment - active states - responsive transitions

The final result should feel like the same category of enterprise
documentation product, not a generic documentation template.
